Proxenos Architecture

A background program on your Linux machine that lets a ChatGPT conversation read and change the folders you choose, through OpenAI's Secure MCP Tunnel. A small terminal app decides what each folder allows.

1 · The big picture

Two worlds, two doors

ChatGPT lives at OpenAI. Your folders live on your machine. Nothing on your machine listens on the internet: a helper program dials out to OpenAI and carries calls back in. Click any box to see what it does, or pick a flow to watch a request travel.

Tip: the two dashed boxes are separate programs. Closing the terminal app never changes what ChatGPT can reach, because the runtime keeps running.

2 · The code

Seven modules, strict walls between them

Each Gradle module has one job. The build itself refuses a module that reaches one it has not declared (build-logic/…/ModuleBoundaryRules.kt), so the walls below are enforced by the compiler, not by good intentions.

Who may depend on whom

Read a row as “this module may use…”. The key wall: tui and control cannot see core, so a frontend can only ever talk to the running runtime, never build its own copy.

Why split core-api from core?

So the question “could a ChatGPT conversation raise an access level?” is answered by the compiler. ChatGPT is handed WorkspaceOperations (the 11 tools). Only the local control socket is handed WorkspaceManagement (register, set level, stop…). They are two different types.

Why no interfaces below the core?

No FileSystem, Clock or ProcessLauncher wrappers. Tests use real temp folders, real git and real child processes. Timeouts and the tunnel binary path are configuration, so a test sets a 200 ms budget and a stub script instead (ADR 0002).

3 · Inside the core

A call's journey through one pipeline

Every tool call, whether it came from ChatGPT or from the terminal app's “try it” button, passes through the same seven checks in WorkspaceOperationsPipeline.kt. Pick a situation and step through it to see where it passes and where it stops.

    What each check protects

    resolve
    The workspace argument is mandatory and must match a name exactly. No “current workspace”, no guessing, even when only one exists.
    level
    The Workspace's dial must be high enough for this tool. The level alone authorizes; there is no per-call prompt.
    confine
    Paths are resolved (symlinks followed) and must land inside the Root. .. and absolute paths are refused.
    key
    Changing tools carry a request_id so a repeat from the tunnel is never run twice.
    lock
    Writes to the same real file wait for each other, even via two overlapping Workspaces.
    Activity
    An entry is written before any change, so a crash leaves a trace.
    outcome
    Exactly one of ok, failed, uncertain.
    4 · Permissions

    One dial per Workspace

    A Workspace is a folder you registered, with a name. Its Access Level is a single dial: None → Read → Write → Command, each including the ones below. New Workspaces start at Read. Turn the dial to see what ChatGPT gets.

    ToolNeedsWhat it doesAt this level

    Lowering the dial is not a stop button. It governs the next call. A build already running keeps running; stop it from the terminal app with s then y.

    One connector, every Workspace. There is one tunnel and one flat catalog of 11 tools. Every tool call names its Workspace, and any conversation that reaches the connector can reach every Workspace above None.

    5 · Results

    Three outcomes, so retries are safe

    Two outcomes (“worked” / “didn't”) would hide the dangerous case: a change that may have happened. The model reads the words, so uncertain says “do not retry” in plain text (ADR 0001).

    ok

    It worked. Here is the result.

    Retry? Not needed.

    failed

    Refused or impossible. Guaranteed: nothing on disk changed.

    Retry? Safe.

    uncertain

    Timed out, stopped, or the folder vanished midway. Effects unknown.

    Retry? No. Repeat with the same request_id to fetch the original answer.

    Entries that need a human look

    The Activity feed flags four unresolved states with a !. They never expire until settled; everything else is kept for 30 days.

    StatePlain meaningHow it settles
    UncertainIt ran; what it did to disk is unknown.You acknowledge it.
    LostThe runtime crashed or was killed while it ran. No result exists.You acknowledge it.
    UndeliveredIt finished, but the answer never reached ChatGPT. ChatGPT thinks it failed.A repeat delivery hands over the stored answer, or you acknowledge it.
    UnclaimedA slow command finished and nobody collected its result.A later get_result, or you acknowledge it.
    6 · Long-running work

    Slow commands get a ticket, not a timeout

    The tunnel re-sends a call it has not heard back from after about 61 seconds, and ChatGPT's own Stop button never reaches this machine. So the runtime answers every call within 45 seconds. A run_command that takes longer keeps running and the call returns a Handle instead. Drag to set how long the command takes.

    20 s
    45 s budget
    ~61 s tunnel re-sends
    0 120 s 240 s

      At most 4 commands at once. Promoted commands keep their slot until they end, so a model stuck in a retry loop cannot start twenty builds. The fifth call is failed (nothing ran, safe to retry).

      One way to kill. Snapshot the process tree, send TERM to the tree and the process group, wait 5 s, then SIGKILL. Anything that survives is named, never rounded off to “stopped”.

      7 · Tunnel health

      What “Connected” can honestly claim

      The runtime reads one number from the tunnel-client every ~15 s: when it last polled OpenAI successfully. Every state is derived from that number plus your own Connect/Disconnect choice (ADR 0005). Press the events to drive the state machine.

      Connecting

      No successful poll yet since start, or since you pressed Connect.

      Connected

      A poll succeeded recently. The link to OpenAI is up.

      Failed

      It worked before and has gone stale. Shows the tunnel's own complaint, word for word.

      Disconnected

      Your choice. Never measured, never a fault.

      What just happened

        Connected does not mean ChatGPT still has the connector. Deleting the connector in ChatGPT leaves the link up and the reading unchanged, and ChatGPT's copy of the tool list is a snapshot that never refreshes. That is why the terminal app shows an “Unconfirmed” banner after install or after an upgrade that changes the tools, until you confirm you re-created the connector (ADR 0007).

        8 · Files and settings

        What is saved, and what is forgotten

        You supply exactly one thing: the credentials file. Everything else has a default.

        Kept across restarts

        registry.properties
        Each Workspace: id, name, Root and Access Level, exactly as set (Command stays Command).
        activity
        The append-only account of every operation. 30 days, unresolved entries kept until settled.
        disconnected
        Whether you last chose Disconnect. Otherwise a start comes up connecting.
        connector
        The tool-catalog fingerprint you last confirmed in ChatGPT.

        All under ~/.local/state/proxenos.

        Forgotten on restart

        Connected state
        Re-measured from scratch.
        Broken
        Recomputed: does each Root still point at the same directory?
        request_ids
        Kept 10 minutes in memory. A restart kills the tunnel child too, so no repeat can arrive.
        running work
        Ended on Stop (left Uncertain) or shown as Lost after a crash.

        Where things live

        credentials
        ~/.config/proxenos/credentials, mode 0600 or the runtime refuses to start. Holds the tunnel ID and runtime key; only the tunnel-client child ever gets them, and run_command strips them from every command's environment.
        config.toml
        Optional overrides beside the credentials file. Never holds the key.
        mcp.sock
        $XDG_RUNTIME_DIR/proxenos/: where tunnel-client delivers ChatGPT's calls.
        control.sock
        Same folder: where frontends connect. The server checks the caller is the same Linux user (SO_PEERCRED).
        bin/wizard
        One-time setup script for the OpenAI dashboard side; writes the credentials file.
        no autostart
        On purpose: after a reboot, nothing is reachable until you start it once. A systemd unit is in docs/ if you disagree.
